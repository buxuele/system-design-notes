# 第11章：设计一个新闻动态系统

## 引言
**新闻动态系统**展示一份持续更新的帖子列表（状态更新、照片、视频和链接），这些信息来自用户的关注关系。典型示例包括 Facebook 的新闻动态、Instagram 的动态流以及 Twitter 的时间线。本章将探讨如何设计一个可扩展的新闻动态系统。

---

## 第1步：理解问题

### 需求
1. **平台：** 系统同时支持 Web 和移动端应用。
2. **功能：**
   - 用户可以发布帖子。
   - 用户可以在新闻动态中查看好友的帖子。
3. **排序：** 为简化设计，动态流按**时间逆序**排列。
4. **规模：**
   - 用户最多可有 5,000 个好友。
   - 日活跃用户数（DAU）为 1,000 万。
   - 动态流可包含文本、图片和视频。

---

## 第2步：高层设计

### 概述
该设计包含两个主要流程：
1. **动态发布：** 用户发布帖子，帖子被写入数据库并推送给其好友的动态流。
2. **新闻动态构建：** 用户通过聚合好友的帖子并按时间逆序排列来获取新闻动态。

---

### 新闻动态 API
1. **动态发布 API：**
   - **端点：** `POST /v1/me/feed`
   - **参数：** `content`（帖子文本）和 `auth_token`（认证令牌）。

2. **新闻动态获取 API：**
   - **端点：** `GET /v1/me/feed`
   - **参数：** `auth_token`（认证令牌）。

---

### 动态发布

1. **用户交互：** 用户通过动态发布 API 发布帖子。
2. **负载均衡器：** 将流量分发到 Web 服务器。
3. **Web 服务器：** 验证请求并转发到相应的服务。
4. **帖子服务：** 将帖子存储到数据库和缓存中。
5. **扇出服务：** 将帖子传播到好友的动态流缓存中。
6. **通知服务：** 向好友发送通知。

---

### 新闻动态构建

   <div style="margin-left:3rem">
      <img src="./images/news-feed-building.png" alt="News Feed Building" width="400">
   </div>

1. **用户交互：** 用户通过获取 API 请求新闻动态。
2. **负载均衡器：** 将流量分发到 Web 服务器。
3. **Web 服务器：** 将请求转发给新闻动态服务。
4. **新闻动态服务：** 从新闻动态缓存中获取帖子 ID，然后从数据库或缓存中检索完整的帖子详情。

## 第3步：设计深入剖析

### 动态发布深入剖析
1. **Web 服务器：**
   - 使用 `auth_token` 验证用户身份。
   - 实施速率限制以防止垃圾信息。

2. **扇出服务：**
   - **写时扇出：** 在写入时将帖子推送到好友的动态流中。
     - **优点：** 实时更新，动态流获取速度快。
     - **缺点：** 对于好友数量众多的用户而言资源消耗大。
   - **读时扇出：** 在读取时拉取帖子。
     - **优点：** 对不活跃用户效率高。
     - **缺点：** 动态流获取速度较慢。
   - **混合方案：** 对大多数用户采用推模型，对高连接数用户（如名人）采用拉模型。

        <img src="./images/feed-publishing-deep-dive.png" alt="Feed Publishing Deep Dive" width="500">

    **扇出服务** 的工作流程如下：

    1. **获取好友 ID：** 从图数据库中检索好友列表。
    2. **从缓存中过滤好友：** 访问缓存中的用户设置，排除特定好友（例如已静音的好友或选择性分享偏好）。
    3. **发送至消息队列：** 将过滤后的好友列表连同新帖子 ID 一起发送至消息队列进行处理。
    4. **扇出工作者：** 工作者从消息队列中检索数据并更新新闻动态缓存。缓存存储的是 `<post_id, user_id>` 映射，而非完整的用户和帖子对象，以节省内存。
    5. **存储到新闻动态缓存：** 将新的帖子 ID 追加到好友的新闻动态缓存中。可配置的限制确保只存储最近的帖子，因为大多数用户关注最新内容，从而保持缓存内存消耗在可控范围内。

## 新闻动态获取深入剖析

### 缓存架构
缓存分为五层：
1. **新闻动态缓存：** 存储帖子 ID 以实现快速检索。
2. **内容缓存：** 存储帖子详情（热门帖子存放在热缓存中）。
3. **社交图谱缓存：** 存储用户关系数据。
4. **行为缓存：** 追踪用户行为（点赞、回复、分享）。
5. **计数缓存：** 维护点赞数、回复数、粉丝数等计数。

## 关键优化

### 扩展性
1. **数据库扩展：**
   - 水平扩展和分片。
   - 使用读副本处理高流量查询。
2. **无状态 Web 层：** 保持 Web 服务器无状态，以支持水平扩展。

### 缓存
1. 将频繁访问的数据存储在内存中。
2. 使用缓存层来降低延迟和数据库负载。

### 可靠性
1. **一致性哈希：** 将请求均匀分发到各服务器。
2. **消息队列：** 解耦系统组件并缓冲流量。

### 监控
1. 跟踪关键指标，如 QPS（每秒查询数）和延迟。
2. 监控缓存命中率并相应调整配置。
